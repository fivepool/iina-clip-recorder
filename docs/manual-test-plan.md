# План ручного тестирования IINA Clip Recorder

## 1. Назначение документа

План предназначен для проверки плагина IINA Clip Recorder в IINA 1.4.4 Build 168 на macOS.

Основной поддерживаемый сценарий MVP — экспорт диапазона из локального видеофайла. Сетевые источники и DRM не входят в гарантированную поддержку MVP.

Статус этапа у теста означает область реализации, а не фактический результат:

| Метка | Этап |
|---|---|
| `VS` | Этап 2: vertical slice — start/end, overlay, локальный MP4, логирование |
| `PREF` | Этап 3: Preferences, настраиваемая клавиша, MP4 1080p/full, output directory, FFmpeg path |
| `GIF` | Этап 4: GIF и надёжный dual export |
| `HARD` | Этап 5: hardening, cleanup, lifecycle и редкие ошибки |
| `LIMIT` | Проверка явно задокументированного ограничения |

Ни одна метка не означает `PASS`. Фактический статус каждого теста нужно записывать отдельно.

Текущий target — Stage 5, версия `0.4.3`. В таблице ниже отдельно зафиксировано
автоматическое покрытие и частичный live smoke через development link.
Частичный smoke не заменяет полного прогона сценария: такой сценарий остаётся
`NOT RUN` полностью, пока не выполнены все его шаги.

| Проверка | Текущий статус | Зафиксированное свидетельство |

## 2. Тестовое окружение

Обязательная конфигурация:

- IINA 1.4.4 Build 168;
- macOS на Apple Silicon;
- FFmpeg, содержащий `h264_videotoolbox` и `libx264`;
- `ffprobe` той же сборки FFmpeg;
- установленный тестируемый `.iinaplugin` или `.iinaplgz`;
- доступ к логам IINA;
- Activity Monitor для наблюдения за нагрузкой и зависшими процессами;
- отдельная папка для тестовых входных и выходных файлов.

Дополнительные конфигурации:

- Intel Mac, если доступен;
- FFmpeg без `h264_videotoolbox`;
- FFmpeg без `h264_videotoolbox` и `libx264`;
- тестовый FFmpeg-wrapper, который контролируемо завершает только MP4- или только GIF-задачу с ошибкой;
- маленький APFS disk image для воспроизведения ошибки недостатка места.

Перед началом серии записать:

- версию и build IINA;
- версию macOS;
- архитектуру и модель Mac;
- версию плагина или commit;
- способ установки плагина;
- путь и вывод `ffmpeg -version`;
- наличие `h264_videotoolbox` и `libx264`;
- текущие настройки плагина;
- результаты `ffprobe` для исходного файла.

## 3. Набор тестовых файлов

Рекомендуется использовать короткие, воспроизводимые и не защищенные авторским правом файлы.

| ID | Характеристики |
|---|---|
| `F01` | 1920×1080, CFR 24000/1001 fps, H.264, AAC |
| `F02` | 3840×2160, CFR 25 fps, H.264 или HEVC, AAC |
| `F03` | 3840×2160, CFR 60000/1001 fps, AAC |
| `F04` | 1080×1920 portrait, CFR 30 fps, AAC |
| `F05` | 1280×720, CFR 30 fps, AAC |
| `F06` | 640×360 или меньше, CFR 25 fps, AAC |
| `F07` | VFR с несколькими заметно различающимися интервалами между PTS кадров |
| `F08` | Видео без аудиодорожки |
| `F09` | Видео с двумя или более аудиодорожками |
| `F10` | Имя и путь с пробелами, кириллицей, emoji, апострофом и скобками |
| `F11` | Файл с rotation metadata, например 90° |
| `F12` | Анаморфный файл, например 720×576 с ненулевым SAR |
| `F13` | Файл с нечетной шириной или высотой |
| `F14` | HDR10/PQ или HLG с корректными color metadata |
| `F15` | Seekable-файл длительностью 305 с: `test-media/generated/15 — 305 second warning source.mp4` |
| `F16` | Локальный файл с несколькими главами и нестандартным Unicode metadata |
| `F17` | Поврежденный или обрезанный файл, который IINA частично воспроизводит, но FFmpeg не может полностью декодировать |

Воспроизводимые Stage 5 fixtures находятся в `test-media/generated/` и
создаются командой `pnpm fixtures:generate`. Их metadata проверяется командой
`pnpm fixtures:verify`, а реальные FFmpeg builders — `pnpm test:media`.
Generated `F15` —
`test-media/generated/15 — 305 second warning source.mp4`; его duration входит
в fixture verification. Range 301 s прошёл live smoke MTP-029 и частично
MTP-051; точные проверки значений непосредственно ниже каждой границы ещё не
выполнены.

Partial-failure проверки используют wrappers
`scripts/fixtures/ffmpeg-fail-gif.sh` и
`scripts/fixtures/ffmpeg-fail-mp4.sh`. Generated media и результаты
интеграционных тестов не входят в release package.

Для проверки диапазона желательно, чтобы `F01` содержал таймкод или заметно меняющуюся картинку и звук.

## 4. Общие критерии проверки результата

Если конкретный тест не устанавливает другое:

- допустимое отклонение начала и длительности MP4 — не более `max(0,15 с; 2 кадра источника)`;
- допустимое отклонение длительности GIF — до 0,25 с с учетом дискретности GIF timing;
- ширина и высота H.264 должны быть четными;
- режимы 1080p и 720p не должны увеличивать исходник;
- display aspect ratio должен совпадать с исходником с относительной погрешностью не более 1%;
- CFR должен сохранить исходную рациональную частоту, например 24000/1001, а не заменяться на 24, 25, 30 или 60 без основания;
- VFR проверяется по PTS отдельных кадров, а не только по `avg_frame_rate`;
- MP4 с аудио должен воспроизводиться синхронно; заметное расхождение аудио и видео недопустимо;
- временный или частично созданный файл не должен выдаваться пользователю как успешный финальный результат;
- после успеха или ошибки state machine должна вернуться в `idle`;
- после завершения не должны оставаться REC/Encoding overlay и временные palette-файлы;
- IINA должна оставаться отзывчивой во время FFmpeg;
- команда должна передаваться как executable плюс массив аргументов. Ошибки shell quoting, интерпретация `$`, обратных кавычек или `;` считаются дефектом.

Для каждого запуска сохранить:

- фактические start/end, показанные плагином или записанные в лог;
- полный путь результата;
- `ffprobe` JSON результата;
- релевантный фрагмент лога IINA;
- screenshot overlay и итогового OSD;
- `PASS`, `FAIL`, `BLOCKED` или `NOT RUN`;
- ссылку на defect при `FAIL`.

## 5. Тестовые сценарии

### MTP-001 — Загрузка development-сборки

**Этап:** `VS`
**Предусловия:** плагин собран и подключен способом, указанным в README.

**Шаги:**

1. Полностью закрыть IINA.
2. Подключить development-пакет.
3. Запустить IINA 1.4.4 Build 168.
4. Открыть окно плеера.
5. Проверить меню плагина и лог IINA.

**Ожидаемый результат:**

- плагин загружается без JavaScript exception;
- пункт запуска записи присутствует в ожидаемом меню;
- статический пункт меню доступен мышью и не содержит key equivalent;
- в секции IINA Clip Recorder всего два пункта: `Start / Stop Clip Selection` и `Show Last Clip in Finder`;
- default Input shortcut `Meta+r` (`⌘R`) зарегистрирован для player window;
- состояние после загрузки — `idle`;
- overlay отсутствует;
- в логе нет циклических ошибок, повторной регистрации обработчика или обращения к неподдерживаемому API.

### MTP-002 — Горячая клавиша без открытого видео

**Этап:** `VS`
**Предусловия:** IINA открыта, медиа не загружено, FFmpeg доступен.

**Шаги:**

1. Нажать горячую клавишу записи.
2. Повторить нажатие через несколько секунд.
3. Проверить overlay, выходную папку и лог.

**Ожидаемый результат:**

- запись не начинается;
- REC overlay не появляется;
- показывается короткое понятное сообщение об отсутствии открытого локального видео;
- файлы и FFmpeg-процессы не создаются;
- state machine остается в `idle`;
- повторное нажатие не ухудшает состояние.

### MTP-003 — Базовый MP4: 1080p, 23.976 fps, AAC

**Этап:** `VS`
**Предусловия:** открыт `F01`; выбран MP4 1080p; GIF выключен; FFmpeg доступен.

**Шаги:**

1. Перейти примерно на 10,000 с.
2. Нажать горячую клавишу.
3. Убедиться, что появился REC overlay.
4. Продолжить воспроизведение до примерно 15,000 с.
5. Нажать горячую клавишу второй раз.
6. Во время FFmpeg управлять паузой, громкостью и размером окна IINA.
7. Дождаться завершения и проверить OSD, файл, лог и `ffprobe`.

**Ожидаемый результат:**

- переходы состояния: `idle → recording → encoding → idle`;
- первый timestamp взят из позиции медиа, а не wall clock;
- REC overlay заменяется на Encoding overlay;
- UI IINA не блокируется;
- создается один непустой `.mp4`;
- видео — H.264, 1920×1080, 24000/1001 fps;
- присутствует AAC-аудио;
- длительность и содержимое соответствуют диапазону 10–15 с;
- итоговый OSD сообщает имя и папку результата;
- команда и диагностический stderr присутствуют в логе без shell quoting errors.

### MTP-004 — Overlay в оконном и полноэкранном режиме

**Этап:** `VS`, полное покрытие `HARD`
**Предусловия:** открыт `F01`.

**Шаги:**

1. Начать запись в оконном режиме.
2. Изменить размер окна до малого и большого.
3. Открыть и скрыть OSC.
4. Перейти в полноэкранный режим и обратно.
5. Попробовать нажимать элементы OSC в области рядом с индикатором.
6. Остановить запись.

**Ожидаемый результат:**

- красная точка, `REC` и elapsed time постоянно видимы;
- индикатор расположен в безопасной области и не обрезается;
- текст читаем на светлом и темном видео;
- overlay не перехватывает мышь и не ломает OSC;
- изменение режима окна не создает дубликаты индикатора;
- после остановки REC overlay гарантированно исчезает.

### MTP-005 — Key repeat и быстрое двойное нажатие

**Этап:** `VS`, hardening `HARD`
**Предусловия:** открыт `F01`.

**Шаги:**

1. Нажать и удерживать горячую клавишу дольше системной задержки key repeat.
2. Проверить состояние и число запусков FFmpeg.
3. Сбросить тест.
4. Дважды намеренно нажать клавишу с интервалом менее 0,1 с.
5. Сразу после этого выполнить нормальную запись длительностью 2–3 с.

**Ожидаемый результат:**

- одно физическое удержание не запускает и не останавливает запись многократно;
- повторные Input events имеют `isRepeat=true`, отбрасываются обработчиком и не полагаются только на time debounce;
- не создаются параллельные или нулевые FFmpeg-задачи;
- намеренный диапазон короче 0,1 с отклоняется с понятным сообщением;
- после ошибки состояние возвращается в `idle`;
- следующая нормальная запись работает без перезапуска IINA.

### MTP-006 — Пауза и изменение скорости во время записи

**Этап:** `HARD`
**Предусловия:** открыт `F01`.

**Шаги:**

1. Начать запись на 10 с.
2. На 12 с поставить IINA на паузу на 5–10 секунд wall clock.
3. Продолжить до 15 с и остановить.
4. Повторить тест со скоростью воспроизведения 2×: начать на 20 с и остановить на 30 с.

**Ожидаемый результат:**

- первый файл содержит примерно 5 секунд медиа, а не 10–15 секунд wall clock;
- elapsed time на паузе не продолжает ложно расти;
- второй файл содержит примерно 10 секунд медиа независимо от скорости 2×;
- timestamps берутся из позиции воспроизведения;
- оба запуска завершаются в `idle`.

### MTP-007 — Перемотка назад до позиции меньше start

**Этап:** `HARD`
**Предусловия:** открыт `F01`.

**Шаги:**

1. Начать запись на 30 с.
2. Перемотать назад на 20 с.
3. Нажать клавишу остановки.
4. Проверить файлы, overlay, OSD и лог.
5. Начать новую корректную запись.

**Ожидаемый результат:**

- отрицательный диапазон не преобразуется молча через `min/max`;
- FFmpeg не запускается;
- пользователь получает сообщение, что конечная позиция раньше начальной;
- REC overlay скрывается;
- состояние возвращается в `idle`;
- следующая запись работает.

### MTP-008 — Автоматическая остановка при EOF

**Этап:** `HARD`
**Предусловия:** открыт локальный файл длительностью не менее 10 с.

**Шаги:**

1. Перейти за 3–5 с до конца.
2. Начать запись.
3. Не нажимать клавишу повторно и дождаться EOF.
4. Проверить результат и состояние.

**Ожидаемый результат:**

- EOF автоматически фиксирует end, ограниченный duration;
- при диапазоне не короче 0,1 с запускается экспорт;
- создается корректный фрагмент до конца файла;
- overlay проходит через Encoding и исчезает;
- повторное EOF-событие не запускает второй экспорт;
- итоговое состояние — `idle`.

### MTP-009 — Смена файла во время recording

**Этап:** `HARD`
**Предусловия:** открыт `F01`, рядом доступен `F02`.

**Шаги:**

1. Начать запись в `F01`.
2. До остановки открыть `F02` в том же окне.
3. Проверить overlay, файлы и лог.
4. В `F02` выполнить нормальную запись.

**Ожидаемый результат:**

- активный диапазон `F01` безопасно отменяется;
- диапазон не продолжается на другом источнике;
- FFmpeg для незавершенного диапазона не запускается;
- overlay скрывается;
- состояние сбрасывается в `idle`;
- пользователь при необходимости получает короткое сообщение об отмене;
- запись в `F02` работает.

### MTP-010 — Закрытие окна во время recording и выгрузка плагина

**Этап:** `HARD`
**Предусловия:** открыт `F01`.

**Шаги:**

1. Начать запись.
2. Закрыть окно плеера.
3. При наличии другого окна IINA проверить отсутствие чужого overlay.
4. Открыть новый файл или перезапустить IINA.
5. Проверить процессы FFmpeg и выходную папку.

**Ожидаемый результат:**

- незавершенный диапазон отменяется;
- FFmpeg не запускается;
- overlay не остается в других окнах;
- после нового открытия состояние — `idle`;
- нет зависшего обработчика, таймера или внешнего процесса.

### MTP-011 — Закрытие окна во время encoding

**Этап:** `HARD`
**Предусловия:** используется достаточно длинный диапазон, чтобы кодирование продолжалось несколько секунд.

**Шаги:**

1. Начать и остановить запись.
2. Убедиться, что появился Encoding overlay и запущен FFmpeg.
3. Закрыть окно плеера.
4. Проверить процесс и выходную папку после ожидаемого времени завершения.
5. Снова открыть IINA.

**Ожидаемый результат:**

- поведение соответствует политике lifecycle, зафиксированной в `implementation-plan.md`;
- плагин не оставляет поврежденный файл под финальным именем;
- если задача продолжается после закрытия окна, результат атомарно становится доступен только после успеха;
- если lifecycle IINA прекращает задачу, временный файл удаляется немедленно или при следующей загрузке;
- после повторного открытия состояние восстанавливается в `idle`;
- зависших REC/Encoding overlay нет.

### MTP-012 — Нажатие shortcut во время encoding

**Этап:** `VS`, полное покрытие `HARD`
**Предусловия:** выполняется длинный MP4 export.

**Шаги:**

1. Во время Encoding нажать shortcut один раз.
2. Затем нажать несколько раз быстро.
3. Проверить процессы FFmpeg, файлы и сообщения.
4. После завершения запустить новую запись.

**Ожидаемый результат:**

### MTP-052 — Cancel/source/window во время confirmation

**Этап:** `HARD`
**Предусловия:** выбран export, который гарантированно открывает confirmation

4. Повторить и быстро дважды нажать `Export`.

### MTP-053 — Замена исходника другим файлом по тому же пути

**Этап:** `HARD`
**Предусловия:** открыт writable local source; подготовлен другой валидный
video-файл, которым можно атомарно заменить source по точно тому же pathname.

**Шаги:**

1. Поставить первый маркер и сохранить исходный fingerprint.
2. Заменить source другим файлом по тому же пути, не меняя pathname.
3. Поставить второй маркер.
4. Повторить замену во время открытой confirmation card перед `Export`.
5. Проверить FFmpeg processes, файлы, сообщение, лог и state.
6. Восстановить исходник и выполнить обычный export.

**Ожидаемый результат:**

- существование того же pathname недостаточно: изменение
  `device/inode/size/mtime` обнаруживается fingerprint-проверкой;
- замена до второго маркера и во время confirmation отменяет export до
  encoding;
- другой файл не кодируется под видом исходного, финальный output не
  появляется, а пользователю показывается понятное сообщение;
- overlay скрывается, state возвращается в `idle`, повторная работа после
  восстановления source возможна;
- известное TOCTOU-ограничение после последней fingerprint-проверки, если оно
  остаётся, фиксируется в отчёте и `known-limitations.md`.

## 7. Проходные наборы по этапам

### Gate этапа 2 — Vertical Slice

Обязательны:

- MTP-001–MTP-005;
- MTP-012–MTP-016;
- MTP-018;
- MTP-025;
- MTP-031;
- MTP-035;
- MP4-часть MTP-048.

Допустимо отложить lifecycle/редкие media cases только при явной записи в known limitations. Нельзя объявлять vertical slice рабочим без проверки в реальной IINA 1.4.4 Build 168.

### Gate этапа 3 — Preferences

Обязательны:

- MTP-017;
- MTP-033;
- MTP-036–MTP-040;
- clean-install target MTP-050 версии `0.4.2`;
- повторный прогон MTP-003, MTP-016, MTP-031 и MTP-035 с сохраненными настройками.

Автоматическая suite проверяет validation и Preferences bridge, но не
засчитывает live IINA сценарии этого gate. Они остаются `NOT RUN` для `0.4.2`.

### Gate этапа 4 — GIF и Dual Export

Обязательны:

- MTP-041–MTP-048;
- повторный прогон MTP-015, MTP-020–MTP-023 для GIF, где это применимо.

Автоматическая suite и real-media integration покрывают builders, palette
workflow и часть media metadata. GIF/dual/partial-success UI и lifecycle
сценарии внутри IINA остаются `NOT RUN` для `0.4.2`.

### Gate этапа 5 — Hardening и Release

Требуется полный прогон MTP-001–MTP-053, кроме явно недоступных аппаратных
конфигураций. Автоматический baseline перед ручным прогоном: 30 TypeScript
tests, 6 WebView/overlay tests, fixture verifier и real-media integration должны
проходить. Любой `BLOCKED` должен быть объяснен в отчете и, если это
продуктовое ограничение, перенесен в `known-limitations.md`.

## 8. Критерии завершения ручного тестирования MVP

MVP может считаться прошедшим ручное тестирование, если:

- все `VS`, `PREF`, `GIF` и применимые `HARD` тесты выполнены на IINA 1.4.4 Build 168;
- нет открытых дефектов, способных повредить исходник, перезаписать существующий файл или оставить state machine зависшей;
- нет открытых дефектов, блокирующих MP4-only, GIF-only или dual export;
- успешный результат каждого формата подтвержден через `ffprobe` и воспроизведение;
- partial failure подтвержден в обоих направлениях;
- UI остается отзывчивым при длительном export;
- cleanup подтвержден после success, failure, смены файла и закрытия окна;
- ограничения HDR, VFR, multi-audio, network/DRM и lifecycle `utils.exec` согласованы с `implementation-plan.md`, README и `known-limitations.md`;
- финальный `.iinaplgz` проверен после чистой установки без development-окружения.
